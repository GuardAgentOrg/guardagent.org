Zero-Trust Agent Action Interception

From Agent Request to Controlled Action

Discover the end-to-end security pipeline that enforces authentication, policy compliance, explainable risk scoring, and human approval before an AI agent touches enterprise infrastructure.

Crucial Architecture Boundary: All security-critical evaluations must occur on the server. Furthermore, an ALLOW decision certifies that the proposed action complied with active policies; it is not proof that downstream external infrastructure executed without error.
01
INGESTION POST /api/requests/evaluate

1. AI Agent Proposes an Action

Autonomous agent frameworks (LangChain, AutoGen, CrewAI, or custom LLM loops) do not connect directly to raw databases or shell subshells. Instead, when an LLM decides to invoke a tool, the agent dispatches a structured JSON payload to the GuardAgent Gateway endpoint.

{ "agent_id": "agt-customer-support-01", "tool_name": "db_write_record", "action_name": "process_refund", "parameters": { "customer_id": "cust_8901", "amount": 1250.00, "reason": "Late shipping courtesy credit" } }
02
ZERO-TRUST CHECK AGENT_REGISTRY_LOOKUP

2. Authentication & Permission Check

The gateway authenticates the agent's identity and checks status in the registry. If the agent is unknown, suspended, or revoked, the request fails closed immediately with an authoritative BLOCK decision.

03
SANITIZATION PAYLOAD_INSPECTION

3. Parameter Inspection & Attack Scanning

The security engine sanitizes and inspects input parameters for known attack vectors:

  • SSRF Target Filter: Prohibits requests targeting link-local metadata (169.254.169.254) or private subnet addresses.
  • SQL Injection Keywords: Detects destructive keywords (DROP, TRUNCATE, ALTER) in database query parameters.
  • Shell Command Traversal: Detects dangerous subshell strings (rm -rf, bash -i, /etc/passwd).
04
GUARDRAIL ENGINE POLICY_EVALUATION

4. Declarative Policy Evaluation

The engine evaluates the action against active policies bound to the agent. Policies apply explicit thresholds and rules:

Evaluated Policy: Financial Transaction Safety Cap

Requested Amount: $1,250.00 • Auto-Allow Limit: $500.00 • Policy Action: REQUIRE APPROVAL

05
SCORING PIPELINE RISK_0_TO_100

5. Deterministic Risk Score Calculation

GuardAgent computes a transparent, explainable risk score (0 to 100) combining tool criticality, argument impact, and policy triggers:

LOW (0–39) • Auto-Allow MEDIUM (40–59) • Heightened Log HIGH (60–79) • Escalate to SOC CRITICAL (80–100) • Hard Block
06
DECISION PATHS GATEWAY_DECISION

6. Deterministic Security Decisions

ALLOW Low Risk (<40)

The action is authorized to proceed through the configured execution path. Dispatched to the tool executor or simulated sandbox.

REQUIRE APPROVAL High Risk (60–79)

The action must wait for an authorized approval. Ticket placed in SOC review queue with a 24-hour expiration safety boundary.

BLOCK Critical Risk (≥80)

The action is denied immediately. Zero downstream tool execution. Security incident alert logged.

07
IMMUTABILITY AUDIT_COMMITTED

7. Controlled Tool Execution & Audit Log

If approved, the tool runs in a restricted sandbox. The complete request lifecycle—including timestamps, correlation ID, policy evaluations, risk score, decision, and reviewer trail—is committed to the immutable audit ledger.
