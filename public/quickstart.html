01

Prerequisites

Before running GuardAgent, ensure you have the following installed on your local development machine:

Node.js

v18.0.0 or later (LTS recommended).

node -v
npm Package Manager

v9.0.0 or later included with Node.

npm -v
cURL or REST Client

For sending mock agent payload requests.

curl --version
02

Clone the Repository

Clone the GuardAgent project or navigate to your local workspace directory:

# Clone the GuardAgent repository git clone https://github.com/guardagent/guardagent.git # Navigate into the project directory cd guardagent
Local Development Notice: If you are working directly in this workspace, you are already in the root directory (d:\GuardAgent).
03

Install Dependencies

Install the required Node.js production dependencies (Express, CORS, dotenv, and @supabase/supabase-js):

# Standard npm installation npm install # On Windows PowerShell (if execution policy restricts npm.ps1): npm.cmd install

Dependencies are lightweight and have zero external native compilation requirements.

04

Configure Environment Variables

Copy the sample environment file to create your local .env configuration:

# Copy template configuration cp .env.example .env

The primary environment variables and their functions are:

Variable Default Description
PORT 3000 HTTP port for the Express web server and REST gateway.
DEMO_MODE true When true, automatically initializes the in-memory security store with preloaded demo agents, policies, and audit logs.
SUPABASE_URL (Empty) Optional. Your remote Supabase project endpoint.
SUPABASE_ANON_KEY (Empty) Optional. Public anonymous client key for Supabase Auth.
SUPABASE_SERVICE_ROLE_KEY (Empty) Optional. Backend service-role key for PostgreSQL table mutations.
05

Configure Supabase (Optional)

GuardAgent is architected to be zero-config ready out of the box:

Option A: Zero-Config Local Mode (Recommended)

Leave Supabase variables unset in .env. GuardAgent automatically defaults to its built-in in-memory store with enterprise demo records. All state changes, approvals, and evaluations remain functional in memory.

Option B: Supabase PostgreSQL Persistence

1. Open your Supabase Dashboard SQL Editor.
2. Execute the migration file at server/database/schema.sql.
3. Paste your project URL and Service Role Key into .env.

06

Start the Application Locally

Launch the GuardAgent daemon server:

# Start via npm script npm start # Or run directly with Node node server/index.js

You will observe startup confirmation banners in your terminal:

======================================================= GuardAgent — AI Agent Security Platform (Beta) Server running at: http://localhost:3000 Public Website: http://localhost:3000/ Beta Application: http://localhost:3000/app/ Health Endpoint: http://localhost:3000/api/health =======================================================
07

Check the Health Endpoint

Verify that the REST gateway is running and operational:

curl -i http://localhost:3000/api/health

Expected HTTP 200 JSON response:

{ "status": "healthy", "version": "1.0.0-beta", "service": "GuardAgent Security Gateway", "timestamp": "2026-10-15T09:30:00.000Z", "engine": { "status": "online", "registered_tools": 5, "active_policies": 6 } }
08

Send a Sample Request

Simulate an autonomous agent proposing an action to the gateway. Dispatch a POST request to /api/requests/evaluate:

curl -X POST http://localhost:3000/api/requests/evaluate \ -H "Content-Type: application/json" \ -d '{ "agent_id": "agt-customer-support-01", "tool_name": "db_read_query", "action_name": "fetch_orders", "parameters": { "customer_id": "cust_1029", "limit": 15 } }'
09

Understand the Security Decision

GuardAgent returns a structured, deterministic security envelope. The 3 possible outcomes are:

1. ALLOW Risk Score: 0 – 39 (Low)

The action complies with all active policy caps (e.g. read limit ≤ 250 rows). The tool executes safely under server controls and returns the execution result.

2. REQUIRE APPROVAL Risk Score: 40 – 79 (High)

The action exceeds auto-allow bounds (e.g. refund between $500 and $2,500). An approval ticket is created (apr-id) with a 24-hour expiration window. The agent must pause and await human review.

3. BLOCK Risk Score: 80 – 100 (Critical)

The action violates an explicit deny policy (e.g. SSRF probe to 169.254.169.254, SQL injection keywords, or revoked agent). Immediate zero-execution drop and security alert logged.

10

Troubleshoot Common Errors

Issue: PowerShell "npm.ps1 cannot be loaded because running scripts is disabled"

Fix: Windows PowerShell execution policy restricts .ps1 script execution by default. Run npm.cmd start or execute directly via node server/index.js.

Issue: Error "EADDRINUSE: address already in use :::3000"

Fix: Another process is occupying port 3000. Specify an alternate port in your environment: PORT=3001 npm start.

Issue: Response returns decision "BLOCK" with rationale "Agent is unregistered"

Fix: Ensure the agent_id specified in the payload exists in the registry. By default, preloaded demo agents include: agt-customer-support-01, agt-code-assistant-01, agt-lead-enrichment-02, and agt-data-pipeline-03.
