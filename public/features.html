Security Controls for Autonomous Agents

GuardAgent provides modular, developer-friendly security components that decouple AI agent reasoning from direct, unverified tool execution.

01

Agent Identity & Role-Based Tool Scoping

Autonomous agents in an enterprise environment must not operate as anonymous actors. GuardAgent enrolls every agent with a distinct identity record, assigned role, operational status (ACTIVE, SUSPENDED, or REVOKED), and explicit permissions defining which registered tools the agent is permitted to invoke.

Enforcement: If an unknown or suspended agent submits a request, or if an enrolled agent attempts to invoke an unauthorized tool, GuardAgent issues a deterministic BLOCK decision before parameter evaluation begins.

02

Declarative Security Policy Enforcement

Security rules must never depend on non-deterministic LLM self-reflection. GuardAgent evaluates declarative rules written in structured JSON and Rego AST schemas. Policies validate numerical thresholds, regex parameter patterns, permitted outbound network CIDRs, and prohibited actions.

EXAMPLE POLICY DEFINITION (DECLARATIVE RULE) JSON SCHEMA 
{
  "policy_id": "pol-ssrf-cloud-metadata",
  "name": "Cloud Instance Metadata Isolation",
  "target_tool": "external_api_call",
  "action": "BLOCK",
  "conditions": {
    "prohibited_cidr": ["169.254.169.254/32", "127.0.0.1/8", "10.0.0.0/8"],
    "deny_message": "Egress request targeted protected cloud metadata endpoint."
  }
}
03

Explainable Risk Scoring Engine

Rather than a binary pass/fail without context, GuardAgent calculates a 0–100 risk score based on tool criticality, parameter magnitudes, policy severity flags, and agent execution history. Every evaluation response includes a clear diagnostic rationale detailing why the score was assigned.

Score Range Risk Level Typical Default Action Example Trigger
0 – 39 LOW ALLOW Read-only query for customer's own order history within limits
40 – 69 MEDIUM ALLOW with Audit Flag Modifying user preferences or staging a draft document
70 – 89 HIGH REQUIRE APPROVAL Financial refund exceeding $1,000 or updating production DNS
90 – 100 CRITICAL BLOCK Attempt to read AWS instance metadata (SSRF) or raw SQL injection
04

Human-in-the-Loop Approval Queue

Autonomous agents should not unilaterally execute high-consequence operations. When a request exceeds a policy threshold, GuardAgent suspends execution and enqueues the action for human review.

  • • Dual-Control Authorization: Sensitive actions require explicit human operator signature token.
  • • SLA Expiration Safeguards: Pending requests expire automatically (default: 24h) and transition to expired state.
  • • Complete Context Display: Human reviewers inspect exact proposed parameters, agent identity, and risk breakdown before deciding.
05

Controlled Tool Execution Proxy

Agents never communicate directly with underlying credentials or network sockets. The GuardAgent controlled executor holds the API secrets and database connections, only dispatching requests that have received a valid ALLOW decision.

Separation of Concerns: By centralizing tool execution within the security gateway, credential exposure to prompt injection leaks is eliminated because the agent never holds raw API keys.

06

Structured, Tamper-Evident Audit Logging

Every decision point, parameter payload, agent ID, and execution state is committed to an append-only event ledger. Correlation IDs link initial requests to final tool outcomes for end-to-end trace auditing.

AUDIT RECORD STRUCTURE SCHEMA 
{
  "correlation_id": "corr-4zfto64w",
  "request_id": "req-13929-w0zs",
  "agent_id": "agt-customer-support-01",
  "tool_name": "db_read_query",
  "decision": "ALLOW",
  "risk_score": 15,
  "execution_status": "COMPLETED",
  "timestamp": "2026-10-19T14:32:01.112Z"
}

Architecture Comparison

How GuardAgent differs from unrestricted execution and purely model-based prompt guards.

Security Dimension Direct Agent Tool Calling LLM Prompt Guardrails GuardAgent Gateway
Execution Boundary None (Direct API invocation) Advisory (Agent can bypass via prompt leak) Authoritative Proxy (Gated network proxy)
Rule Determinism Non-deterministic Probabilistic (Subject to model hallucination) Deterministic (Compiled Rego/JSON AST)
Human Approval Workflow Ad-hoc custom code Not supported Built-in (Stateful review queue)
Credential Isolation Secrets passed to agent context Secrets passed to agent context Isolated in gateway proxy
Audit Tracing Scattered application logs Chat transcript only Structured SHA-256 event ledger
