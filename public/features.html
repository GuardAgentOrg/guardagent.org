CORE MODULE 01 IMPLEMENTED IN BETA

Agent Identity & Registration

Autonomous agents cannot execute any tool actions anonymously. Every agent must be registered with a unique server-generated identifier (agt-id), bound to an organizational workspace, and issued single-exposure API credentials.

  • Zero-Trust Identity: Enforces cryptographic API keys per agent.
  • Instant Kill-Switch: Operators can immediately toggle agent status to SUSPENDED or REVOKED to instantly stop compromised agents.
  • Environment Scoping: Isolate testing, staging, and production agent fleets.

CORE MODULE 02 IMPLEMENTED IN BETA

Policy Enforcement

GuardAgent enforces declarative security guardrails before tool execution. Rather than relying on non-deterministic LLM system prompts, security constraints are calculated and executed strictly on the server backend.

  • Financial Guardrails: Auto-allow payments <$500, require human approval for $500–$2,500, block >$2,500.
  • Database Read Limits: Restrict bulk dumps by enforcing a maximum row count ceiling (default 250).
  • SSRF Domain Allowlists: Block internal IP ranges (169.254.169.254, 127.0.0.1) and restrict egress to verified domains.
  • Destructive Keyword Filters: Auto-block SQL injection vectors (DROP, TRUNCATE) and shell escapes.

CORE MODULE 04 IMPLEMENTED IN BETA

Human Approval Workflows

High-risk or financially sensitive actions trigger an automatic human escalation ticket. The agent's requested execution is paused while human security officers review the proposal.

  • 24-Hour Expiration Boundary: Unreviewed requests automatically expire and fail closed to avoid stale execution.
  • Audited Sign-Off: Operator notes, identity, and timestamps are recorded in the immutable log.
  • One-Click Resolution: Approve or Reject directly from the SOC web interface or REST API.

CORE MODULE 05 IMPLEMENTED IN BETA

Audit Logs & Real-Time Alerts

Complete historical traceability for autonomous AI operations. GuardAgent generates immutable audit records containing the exact input parameters, policy evaluations, risk score, decision, and reviewer trail.

  • Cryptographic Correlation IDs: Trace individual agent sessions across multi-step execution flows.
  • Prohibition of Deletion: Audit tables reject HTTP DELETE or PATCH operations with a strict 405 error.
  • Automated Incident Alerts: Critical risk violations (e.g. SSRF attempts) immediately trigger security incidents.

CORE MODULE 06 IMPLEMENTED IN BETA

Controlled Tool Execution

When an action is evaluated as ALLOW, it is dispatched to GuardAgent's tool executor. GuardAgent validates parameter boundaries, isolates downstream credentials, and provides safe simulated mock tool sandboxes for testing.

  • Registered Catalog: Only tools pre-registered in server/services/toolRegistry.js are permitted.
  • Credential Isolation: Agents never receive raw API keys or database connection strings.
  • Execution Boundary: An ALLOW verifies policy compliance; external tool failure does not invalidate security posture.
