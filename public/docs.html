01 Introduction

GuardAgent is an enterprise AI agent security gateway. It sits between autonomous LLM agent frameworks (such as LangChain, AutoGen, CrewAI, or bespoke agents) and protected enterprise tools (databases, external APIs, code execution sandboxes, and file systems).

Modern AI agents have the ability to formulate tool calls and execute actions autonomously. While powerful, this introduces serious security vulnerabilities: prompt injections causing unintended database drops, SSRF probes attacking internal cloud metadata services, and unconstrained financial transactions. GuardAgent provides a server-enforced security perimeter to evaluate every action before execution.

Core Mission: Make policy enforcement, explainable risk scoring, and human-in-the-loop approvals standard building blocks for AI development.

02 Architecture & Trust Boundaries

GuardAgent enforces a strict server-side security boundary. Agents must never hold raw database passwords, cloud credentials, or unrestricted shell access. Instead, all proposed actions are routed to GuardAgent's proxy gateway:

[AI Agent (LangChain / AutoGen / CrewAI)] │ (Proposes JSON action payload) ▼ [GuardAgent Security Gateway: POST /api/requests/evaluate] │ ├── 1. Agent Identity & Key Authentication ├── 2. Workspace & Permission Boundaries ├── 3. Injection Filters (SSRF, SQLi, Shell Escapes) ├── 4. Declarative Policy Evaluation ├── 5. Deterministic Risk Scoring (0–100) ▼ [Security Decision Engine] ├── ALLOW ──────────────► [Controlled Tool Sandbox] ──► [Tool Result] ├── REQUIRE APPROVAL ──► [SOC Review Queue] ─────────► [24h Expiration Timer] └── BLOCK ──────────────► [Immediate Termination] ───► [Security Alert Logged] │ ▼ [Immutable Audit Ledger (PostgreSQL / In-Memory Store)]

All decisions and risk justifications are logged to an append-only audit ledger with cryptographic correlation identifiers.

03 Installation

GuardAgent requires Node.js v18.0.0 or higher. To install and run locally:

# 1. Clone repository git clone https://github.com/guardagent/guardagent.git cd guardagent # 2. Install dependencies (Node Express, CORS, dotenv, Supabase client) npm install # Note: On Windows PowerShell if script execution is restricted: npm.cmd install

05 Authentication

GuardAgent employs two distinct authentication mechanisms depending on the caller type:

1. Agent Gateway Authentication

AI agents authenticate by supplying their registered API key via the x-guardagent-key HTTP header or in the request payload:

curl -X POST http://localhost:3000/api/requests/evaluate \ -H "Content-Type: application/json" \ -H "x-guardagent-key: ga_live_agent_key_demo" \ -d '{"agent_id": "agt-customer-support-01", ...}'

2. Operator Dashboard Authentication (SOC Users)

Security operators authenticate via POST /api/auth/login. In production, this integrates with Supabase Auth (JWT). In local DEMO_MODE=true, operators can log in using preloaded SOC credentials or 1-click instant login.

06 Agent Registration & Lifecycle

Before an AI agent can execute any tool call through the gateway, it must be enrolled in the agent registry:

POST /api/agents
curl -X POST http://localhost:3000/api/agents \ -H "Content-Type: application/json" \ -d '{ "name": "Research Agent Alpha", "description": "Autonomous web scraper and document summarizer", "policy_id": "pol-p03-ssrf-guard", "environment": "production" }'

Agent Status Lifecycle

  • ACTIVE: Agent is authorized to propose actions against assigned policies.
  • SUSPENDED: Temporarily locked. All incoming tool requests fail closed with BLOCK.
  • REVOKED: Permanently decommissioned. API keys are immediately invalidated.

07 Security Policies & Rules

Policies define the strict boundaries of acceptable agent behavior. GuardAgent implements declarative rules covering:

Financial Transaction Limits

Auto-allow payments under $500. Require human SOC approval for $500–$2,500. Outright block transactions >$2,500.

Database Row Ceilings

Enforce maximum row count (default: 250). Prohibit full table scans and bulk dumps.

SSRF & Egress Allowlists

Block link-local addresses (169.254.169.254) and loopbacks. Whitelist approved API domains.

Command Blacklists

Detect and reject destructive SQL keywords (DROP, TRUNCATE) and shell commands.

08 Risk Evaluation Engine

Every proposed action is evaluated through GuardAgent's deterministic risk engine. The engine outputs a numerical score from 0 to 100, broken down into human-readable rationale factors:

Score Range Risk Tier Default Decision Action Path
0 – 39 LOW ALLOW Dispatched to registered tool / sandbox for execution.
40 – 59 MEDIUM ALLOW (with Log) Allowed under heightened audit monitoring.
60 – 79 HIGH REQUIRE APPROVAL Escalated to human review queue with 24h expiration.
80 – 100 CRITICAL BLOCK Terminated immediately; zero tool execution; alert raised.

09 Approval Workflows (Human-in-the-Loop)

When an action triggers a policy escalation (e.g. high-value refund or elevated API parameter), GuardAgent pauses execution and creates an approval request record:

POST /api/approvals/:id/decide
curl -X POST http://localhost:3000/api/approvals/apr-2026-001/decide \ -H "Content-Type: application/json" \ -d '{ "decision": "APPROVED", "reviewer_notes": "Verified with finance team via ticket #FIN-8812." }'

Security officers can inspect full argument parameters, evaluate risk factors, and either approve or reject the request. Once approved, the tool executes under bounded limits.

10 Audit Logs & Integrity

Every incoming action—regardless of outcome—is stamped with a persistent correlation ID and saved to the immutable audit log:

GET /api/audit-logs
Immutability Guarantee: Audit log records cannot be updated or deleted via API. Attempts to perform HTTP DELETE or PATCH against /api/audit-logs return an explicit 405 Method Not Allowed error.

11 API Reference

All implemented REST endpoints in the GuardAgent Gateway:

GET /api/health

Returns service health, registered tool count, and active policy status.

POST /api/requests/evaluate

Core security gateway endpoint. Evaluates proposed agent action against policies, calculates risk, and returns ALLOW, BLOCK, or REQUIRE APPROVAL.

GET /api/agents  |  POST /api/agents

List registered agents or enroll a new autonomous agent.

PATCH /api/agents/:id/status

Toggle agent operational status (ACTIVE, SUSPENDED, REVOKED).

GET /api/policies  |  POST /api/policies

Manage declarative security guardrails, financial caps, and row ceilings.

GET /api/approvals  |  POST /api/approvals/:id/decide

List pending human escalation tickets or submit an approval/rejection decision.

GET /api/audit-logs

Query immutable chronological security events with filtering by decision, agent, or risk level.

GET /api/alerts

Fetch security alerts raised by critical risk violations, SSRF attacks, or SQL injection probes.

GET /api/analytics/metrics

Aggregate SOC telemetry: total requests, allowed vs blocked ratios, and risk score distributions.

12 Troubleshooting

Q: Why did my agent receive a BLOCK decision with "Unknown tool"?

GuardAgent enforces deny-by-default. Only registered tools in server/services/toolRegistry.js (e.g. db_read_query, db_write_record, external_api_call, send_email_notification, exec_code_sandbox) are permitted.

Q: How do I test the Human Approval workflow?

Send an action payload with a refund amount between $500 and $2,500 using tool db_write_record. The gateway will return REQUIRE APPROVAL and create an entry in the Pending Approvals queue.

Q: Can I run GuardAgent completely offline without cloud dependencies?

Yes! GuardAgent operates in zero-config local mode by default, persisting state in memory and using local mock tools.
