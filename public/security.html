Hardened Server-Side Enforcement Perimeter

Security Architecture & Trust Boundaries

Security cannot be enforced via client-side prompts or non-deterministic LLM promises. GuardAgent enforces zero-trust boundaries at the server level.

Technical Honesty & Beta Security Notice: GuardAgent is currently in public beta. While built strictly according to enterprise defense-in-depth engineering principles, it has not yet completed an independent third-party SOC 2 Type II or external cryptographic penetration audit. Do not deploy directly in unregulated multi-tenant environments without sandbox testing.

Core Security Design Principles

The architectural pillars that govern every request entering the GuardAgent security gateway.

1. Server-Side Enforcement

Client-side restrictions can be bypassed by jailbroken LLMs. GuardAgent performs all authentication, parameter sanitization, policy matching, and risk evaluation strictly on the backend.

Strict Backend Gateway

2. Deny-by-Default

If an agent is unregistered, suspended, lacks an assigned policy, or if an unexpected exception occurs during parsing, the gateway fails closed with an authoritative BLOCK decision.

Fail-Closed Posture

3. Secret Management

AI agents are never granted direct database connection strings, cloud IAM credentials, or upstream API secrets. Secrets reside exclusively in server environment variables.

Zero Secret Leakage

4. Injection & SSRF Defense

Inbound parameters are scrubbed for SSRF metadata IPs (169.254.169.254), SQL injection keywords (DROP, TRUNCATE), and dangerous subshell escape sequences.

Parameter Heuristics

5. Declarative Policies

Security rules are written as declarative JSON policies, separating code logic from security configuration. Adjust financial caps or row limits without rebuilding application code.

Declarative Guardrails

6. Explainable Risk Logic

Calculates a deterministic 0–100 risk score based on tool criticality, parameters, and violations. Every score provides clear rationale factors for security audits.

Deterministic Scoring

7. Human Escalation Guards

Actions requiring approval are held in an authorized review state. If an operator does not review within 24 hours, the request automatically expires to prevent stale execution.

24h Expiration Timer

8. Immutable Audit Records

Audit records are append-only. Backend REST endpoints strictly reject HTTP DELETE or PATCH against /api/audit-logs with a 405 Method Not Allowed response.

Non-Deletable Ledger

9. PostgreSQL RLS Isolation

When connected to Supabase, Row Level Security policies enforce strict tenant isolation so that public or unauthorized callers cannot view or alter foreign agent configurations.

Multi-Tenant Isolation
