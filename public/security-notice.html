Security Architecture & Boundaries

A transparent overview of GuardAgent's security model, defense layers, architectural boundaries, and explicit limitations.

Core Security Architecture Principles

GuardAgent is engineered around four fundamental tenets of infrastructure security:

PRINCIPLE 01

Decoupled Execution Boundaries

AI agents should never maintain direct network access to production databases or internal APIs. GuardAgent acts as an authoritative reverse proxy: the agent only possesses credentials to request an action from GuardAgent.

PRINCIPLE 02

Deterministic Rule Evaluation

GuardAgent rejects using an LLM to police another LLM. GuardAgent relies strictly on declarative compiled AST rules, CIDR network calculations, and numeric boundary checks that execute in 0.8ms.

PRINCIPLE 03

Deny-by-Default Security Model

Any request missing an authenticated agent ID, referencing an unapproved tool, or containing unrecognized parameters is rejected immediately. Access is granted only when an explicit rule permits it.

PRINCIPLE 04

Immutable Auditability

Every decision includes a correlation ID, evaluation timestamp, diagnostic rationale, and SHA-256 integrity hash for forensic review and SOC 2 / HIPAA compliance verification.

Explicit Security Boundaries & Limitations

Understanding what GuardAgent does and does not do is essential for effective security engineering:

1. ALLOW Decision Scope

An ALLOW decision from GuardAgent means that the proposed action complied with all configured GuardAgent safety policies at the moment of evaluation. It does not guarantee that the downstream API service will execute without error.

2. Model Weight & Reasoning Independence

GuardAgent operates strictly at the network gateway boundary. It intercepts structured tool calls (JSON payloads). GuardAgent does not inspect or modify LLM internal neural weights or hidden layer activations during text generation.

3. Policy Completeness Dependency

The gateway strictly enforces the rules defined by your engineering team. If a sensitive tool is registered without restrictive policy bounds, GuardAgent will permit execution in accordance with the configured policy.

Official Security Notice & Vulnerability Disclosure

GuardAgent treats security vulnerabilities in the gateway runtime, policy AST parser, and SDK with top priority. As a compiled safety switch deployed in mission-critical environments, we enforce strict responsible disclosure procedures.
