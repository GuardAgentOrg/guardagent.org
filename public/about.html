OUR MISSION & ARCHITECTURE

Securing the Autonomous Frontier of AI Agents

GuardAgent is an open-source initiative dedicated to establishing transparent, policy-driven security controls between autonomous AI reasoning and real-world tools.

Why GuardAgent Exists

Autonomous AI agents are shifting software engineering from static, pre-programmed execution to probabilistic, model-driven decision-making. When agents are granted tool-calling capabilities — executing SQL queries, calling external APIs, modifying file systems, or transferring funds — traditional perimeter firewalls and static IAM roles are no longer sufficient.

An agent compromised by prompt injection, jailbreaking, or reasoning divergence can attempt catastrophic actions within legitimate API boundaries.

GuardAgent was founded on a simple principle: Do not trust LLM output implicitly when interacting with critical infrastructure. By decoupling security policy enforcement and risk analysis from agent reasoning, GuardAgent creates an independent, verifiable security perimeter.

Core Philosophy: LLM agents suggest intentions; GuardAgent validates identity, enforces deterministic policies, calculates risk, orchestrates human review, and dispatches tools under strict controls.
GUIDING VALUES

Engineering Principles

How we design, review, and build GuardAgent's security architecture.

1. Deterministic Over Heuristic

While we utilize contextual risk scoring, absolute security boundaries are governed by deterministic, verifiable rules. Critical commands (like dropping tables or accessing cloud metadata) are blocked by code, not prompt suggestions.

2. Fail-Safe Deny-by-Default

If a request is malformed, an agent is unauthenticated, a database lookup times out, or an internal engine exception occurs, the action is unconditionally denied. The gateway never fails open.

3. Radical Transparency

Every security evaluation generates an immutable audit record and an explainable rationale. Developers and security auditors can inspect precisely why an action was permitted, flagged, or rejected.

DEVELOPMENT STATUS

Current Release vs. Roadmap

Honest, unambiguous accounting of implemented capabilities and planned features.

Currently Implemented (v1.0.0-beta)

LIVE

Fully functional in the current repository codebase and verified by automated unit tests:

  • 12-step Security Pipeline: Input sanitization, agent authentication, AST policy matching, risk factor scoring, and decision engine.
  • Deterministic Tool Mediation: Safe execution dispatch for registered mock tools (SQL, HTTP, filesystem, financial ledger).
  • Zero-Config Local Storage: Complete in-memory datastore with pre-seeded demo fixtures for instant local testing.
  • Optional Supabase Integration: PostgreSQL client connectivity for persistent multi-tenant deployments.
  • Human Approval Queuing: State machine holding sensitive requests with expiry enforcement and administrative review.
  • Immutable Audit Ledger: Append-only security event logger with tamper-resistant DELETE prohibition.

Planned Roadmap

IN DEVELOPMENT

Under architectural review and prioritized for upcoming minor and major releases:

  • eBPF Kernel Sandboxing: OS-level process isolation and syscall filtering for autonomous coding agents running locally.
  • Distributed Raft Consensus: High-availability multi-node clustering for enterprise failover and low-latency global deployments.
  • Open Policy Agent (OPA) / Rego Support: Native compilation of Rego rules alongside JavaScript AST guardrails.
  • Hardware Security Module (HSM) Signing: Cryptographic tamper-proofing of audit records via PKCS#11 keys.
  • Community Policy Registry: Curated repository of pre-packaged security templates for popular agent frameworks (LangChain, AutoGen, CrewAI).
